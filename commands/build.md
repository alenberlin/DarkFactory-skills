Implement the current plan using `incremental-implementation`, driven by `test-driven-development`.

$ARGUMENTS

For each approved slice, write a meaningful failing test, implement the behavior, refactor green and verify. Commit only under explicit recorded permission. In runtime mode, submit a scoped candidate for protected checks, independent review and trusted integration. Use `source-driven-development` for uncertain external APIs and `debugging-and-recovery` for failures.

**`/build auto`:** execute the approved task plan without routine intermediate confirmation. Respect its permissions and bounded repair limits. An interactive command does not establish durable background execution; use `/factory` and a supervised worker for that.
