# Acceptance Validation

For the actual delivery revision, map every mandatory requirement and acceptance criterion to current trusted checks and independent review coverage. Reject missing, failed, stale, skipped or merely asserted evidence. Include outstanding findings, limitations, setup instructions and actual runtime observations.

Engineering readiness and human acceptance are distinct states. The acceptance auditor can recommend readiness; only the authenticated human channel records acceptance bound to the exact delivery digest. An agent-authored approval file, header or status field cannot replace it.

If the human rejects a delivery, preserve feedback, revision and original task history. Create separate criterion-linked corrective tasks with inherited permissions and dependencies, and repeat verification/review before presenting a new revision. Verify required README/runbook files in the actual delivered source. Never weaken criteria to accommodate a defect. Human finding exceptions are exact-revision administrative actions and never waive required checks. Acceptance does not authorize deployment, publication or unrelated external effects.
