# Product Discovery

Turn the user’s goal into observable requirements before selecting implementation tasks. Read existing product material first. Ask only unresolved questions that change users, scope, behavior, data, security, integrations or success criteria. Recommend an answer where evidence supports it; preserve the human’s decisions.

Record user journeys, domain vocabulary, functional and nonfunctional requirements with stable IDs, constraints, non-goals, assumptions and unresolved decisions. Never silently assume a consequential answer. For existing systems, map requested changes to current behavior and migration risks.

Hand the product analyst’s PRD to architect and implementation-planning. Produce a proposed blueprint, not an approved run. The administrative channel records human approval after the complete architecture, plan, verification and permissions are reviewable.
